# ScreenDock

当前版本 v20：Windows 原生工具风，自动读取亮度与模式支持，主界面可直接选择内置模式；已修复显示器重复识别和最大化布局，并合并窗口尺寸变化时的重复布局更新；布局图随尺寸变化完整重绘，清除旧位置的屏幕图案。

轻量 Windows 10/11 x64 多显示器管理工具，C# / .NET Framework，MIT 许可。

## 功能

- 屏幕布局、编号识别、停用/启用及倒计时确认。
- 托盘运行、逐屏硬件亮度。
- **v4：自动识别型号、检测显示器内置色彩/画面模式、试用和恢复。**
- 型号配置文件、去除设备实例路径和序列号的模式诊断报告。

双击 `ScreenDock.exe`。选中屏幕后等待自动检测，在“内置模式”一行选择模式并点击“应用”。更多操作在“屏幕 → 内置模式与诊断”中。15 秒内确认保留，否则尝试恢复。上次切换前的可读取设置也可以手动恢复。

## 自动适配原则

从 Windows WMI 的显示器标识读取型号，以 DDC/CI capabilities 中明确列出的值为候选。只开放可读取当前值的 **VCP 0x14 色彩预设**和 **0xDC 画面模式**，不猜测支持范围，不尝试厂商私有写入。

有些固件使用 `E2A004` 等扩展标记；解析器跳过这些完整标记及参数，继续解析后续标准功能，不将它们误认成标准字节指令。

标准色彩名称按 MCCS 通用定义显示，厂商实现可能不同。画面模式尚未核实对应名称时显示原始十六进制编号。仅成功回读不等于所有模式都已实测。

## 当前实机验证（2026-10-16）

| 型号 | 检测结果 | 实际切换验证 |
| --- | --- | --- |
| Philips 275M1RZN / PHLC25B | 8 个色彩候选；0xDC 虽有声明但读取失败，因此隐藏 | 6500K → 7500K → 6500K，均回读匹配；亮度、对比度、RGB 增益与原值一致 |
| Philips 27M2N6800ML / PHLC34D | 9 个色彩候选、19 个画面候选；能力型号为 MStar，Windows 型号可识别 | 只读检测，未切换；画面模式保留编号，名称未核实 |

并不保证所有显示器支持。内置屏幕、扩展坞、HDR、固件与画面预设可能影响可读写性。一个逻辑显示器对应多个物理显示器时不开放模式写入。

## 恢复与隐私

试用前备份可读取的模式、亮度、对比度和 RGB 增益到 `%LOCALAPPDATA%\ScreenDock\mode-recovery-<硬件型号>-<实例哈希>.xml`，备份含本地设备实例标识以防恢复到错误设备。此文件不属于源码，也不会上传。退出或崩溃时不能保证自动回滚，可重新打开软件尝试手动恢复。恢复不覆盖无法读取或私有的设置；模式可能影响这些设置，不能保证完全还原厂商内部状态。

每个设备实例分别保留一份恢复文件。相同型号的多台屏幕不会共用记录，恢复时还会核对设备实例标识。

“导出诊断”仅保存型号、标准候选列表、当前模式和检测说明，不保存原始能力字符串、序列号或完整设备实例路径。程序不联网。

## 构建与测试

在 PowerShell 中执行：

```powershell
.\build.ps1
.\test.ps1
```

使用 Windows 的 `%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe`。无第三方依赖。测试覆盖能力解析中的厂商扩展、稀疏枚举、大小写、重复值、损坏字符串和设备标识。

源码：`src/ScreenDock.cs` 为主窗口和 Win32 接口，`Design.cs` 为绘制控件，`Brightness.cs` 为亮度，`MonitorModes.cs` 为能力检测/适配/备份恢复，`ModeDialog.cs` 为内置模式界面。

## 贡献型号适配

见 [适配指南](profiles/README.md)。当前配置只能补充型号名称和已公开模式的标签，不会增加未知指令。提交模式别名时请附型号、固件、诊断和真实 OSD 对应证据；不要提交序列号或本地恢复文件。
